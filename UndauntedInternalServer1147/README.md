# UndauntedInternalServer for Dauntless 1.14.7

Port of `UndauntedInternalServer` (Dauntless 1.4.4) to the **1.14.7** client
(`dauntless_rel-1.14.7_Shipping_2024-04-01`, CL 647472, UE 4.26.2, exe SHA-256 `F3F95FBF…`).
The DLL refuses to start on any other build.

## What changes from the 1.4.4 DLL

- `SDK/` is a fresh Dumper-7 dump of 1.14.7 (see `PORT-1.14.7/sdk-out/README.md`).
- Every address lives in `Addresses1147.h`, with the first bytes expected at each one.
  `Hooking.h` checks those bytes before hooking or patching and logs `[hook] FAILED …`
  instead of corrupting memory. Evidence for each address: `PORT-1.14.7/04-addresses-net.md`
  and `05-addresses-misc.md`.
- No EOS: `UseEOS()` returns false and `-DisableEOS -NoEAC` are added to the command line the
  engine sees, so 1.14.7 uses the same Phoenix/MCP login as 1.4.4. Nothing depends on Epic.
- `Endpoints1147.h` (generated by `PORT-1.14.7/tools/gen-endpoints.js`) redirects the 193
  `[OnlineSubsystemPhoenix]` keys of 1.14.7 to the metagame.
- Strings handed to the engine are allocated with the engine's `FMemory::Realloc`
  (`EngineString.h`): Dumper-7's `FString(const wchar_t*)` does not copy.
- Fixes carried over from the analysis: `InitListen` is vtable `+0x290` (not `+0x280`), the
  notify pointer is `World + 0x28` (so the 1.4.4 TickDispatch hook is gone), the net driver comes
  from `FindNamedNetDriver`, and the two "IsNetReady / IsLevelInitForActor" hooks the 1.4.4 source
  had swapped now point at the right functions.

The project defines `_DISABLE_CONSTEXPR_MUTEX_CONSTRUCTOR`: the game loads an older
MSVCP140.dll, and a `std::mutex` built with the constexpr constructor crashes it on the first lock.

What made combat work, in order (details in the code comments):
1. The server issues the progression configuration query itself (`KickProgressionConfiguration`). Otherwise only the
   client's login screen asks for it, and every player-data loader waits behind it until the 60 s timeout.
2. Ability RPCs are replaced by `InternalTryActivateAbility` (`ProcessEventHook`), as in the 1.4.4 DLL.
3. Replication runs at the start of `UNetDriver::TickFlush` (push-model dirty marks; found on 2.1.1).
4. Our driver is set on the world's level collections: `UWorld::SetActiveLevelCollection` copies the collection's
   (null) driver into `World->NetDriver` during the world tick, so every gameplay RPC was dropped (found on 2.1.1;
   the 1.4.4 DLL patched the same lookup with its `GetNetDriverInternal` hook).

Diagnostics: `DR_LOG_FILE` (the log, the engine's own included), `native-fault-<pid>.log` in `GAMESERVER_READY_DIR`
(access violations), and a `[perf]` line every 10 s on servers.


## Run a test server

Same argument contract as the 1.4.4 DLL. The DLL must load before the engine starts: put
`UndauntedProxy/winmm.dll` and this DLL next to `Dauntless-Win64-Shipping.exe` (removing both restores the game), or
start the exe with `PORT-1.14.7/tools/injector/inject.exe ... early`:

```bash
inject.exe <Win64>/Dauntless-Win64-Shipping.exe <Win64> x64/Release/UndauntedInternalServer.dll early <apikey> 8777 /Game/Maps/ramsgate/ramsgate_01_persistent NO_BEHEMOTH NO_MM_HUNTID NO_EXPECTED_PLAYERS 127.0.0.1:8777 -server
```

Environment: `DR_LOG_FILE` (log file instead of a console; the engine's own log goes there too),
`DR_METAGAME_ADDRESS` (default `127.0.0.1:61000`), `DR_SERVER_READY_FILE`, `GAMESERVER_READY_DIR`,
`DR_SERVER_MAX_FPS`.
